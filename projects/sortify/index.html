Windows desktop utility / project 01

Sortify.

Name every file by what is inside it.

Sortify turns a risky batch operation into a visible plan. It reads bounded excerpts from supported files, suggests clearer names, and waits for approval before touching anything.

01

Why it exists

Problem & motivation

Bulk renaming is repetitive and stressful: a single bad rule can affect dozens of files, and opaque automation is difficult to trust with personal documents.

The spark

The idea was to make file organisation predictable, local-first, and reversible — not a blind batch command that hopes for the best.

The approach

Sortify separates understanding a file, proposing a name, previewing the full plan, applying safe renames, and recording history so the last session can be undone.

02

Direction

Goals and design decisions

  1. 01

    Make the exact before-and-after plan visible before any file changes.

  2. 02

    Respect collisions, unsupported files, and per-file failures instead of silently overwriting.

  3. 03

    Keep the default workflow offline and make external AI naming explicitly opt-in.

  4. 04

    Treat undo as a first-class part of the utility.

01

Preview before execution

Proposals can be edited inline and the Preview plan dialog lists the exact batch before it runs.

02

Local first, AI by consent

A local heuristic engine is the default. An OpenAI-compatible endpoint is available only after explicit consent.

03

Safety in the rename engine

Collisions are detected before the batch, files are never overwritten, and failures are reported per file.

04

Recoverable history

Applied batches are stored in local SQLite history, enabling Undo last session when it is still safe.

05

Bounded extraction

Only bounded excerpts and supported formats are read; protected, oversized, and image-only PDFs fall back safely.

03

Implemented

What the repository actually contains

These features are described in the project README or visible in its source and release material.

Content-aware naming

Reads PDF, Word, Excel, PowerPoint, text/data formats, and image metadata.

Two naming engines

Uses an offline local heuristic engine or a configurable OpenAI-compatible endpoint.

Editable review

Shows status, rationale, extracted text, and inline proposal edits in the Review view.

Collision-aware renames

Detects duplicate destinations before applying and never overwrites files.

Undo history

Records applied sessions in SQLite and can restore original names when still safe.

Windows packaging

Ships installer, portable, and standalone builds with SHA-256 checksums.

Reflection

Contribution, challenges & scope

My contribution

  • I authored and maintain the public repository under my GitHub account, hmmlavi.
  • The repository contains the PySide6 interface, scanning, extraction, validation, rename, and history modules.
  • It also includes unit and GUI smoke tests, Windows packaging scripts, CI, and release documentation.

Challenges & learning

Edge cases matter
Unsupported files, password-protected PDFs, collisions, and partial failures all need clear outcomes.
Privacy by default
File excerpts stay local unless a user configures an endpoint and accepts the AI consent flow.
Distribution is part of the product
The release workflow builds and verifies Windows installer and portable packages.

Documented limits

These are boundaries stated in the repository, not completed features:

  • No OCR is bundled; image-only PDFs fall back to filename and metadata.
  • Release builds are not code-signed, so Windows SmartScreen may warn before running them.
  • External AI naming is optional and requires a configured endpoint; API keys stay in the OS keyring.
